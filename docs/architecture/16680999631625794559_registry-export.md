# Registry Export API

The registry export system provides a serializable view of the entire model registry, designed for RPC boundaries and external integrations.

## Problem

When exposing the `ModelRegistry` through an RPC interface, consumers previously couldn't access full registry information without making N+1 calls:

```rust
// Old approach: N+1 calls
let models = registry.list_models();           // 1 call
for model in models {
    let info = registry.get_model_info(model); // N calls
}
```

## Solution

The `export()` method returns a complete `RegistryExport` in a single call:

```rust
let export = registry.export();
// Now have: services, families, models, and stats
```

## Data Structures

### RegistryExport

Complete registry snapshot:

```rust
pub struct RegistryExport {
    pub services: Vec<ServiceExport>,
    pub families: Vec<String>,
    pub models: Vec<ModelExport>,
    pub stats: RegistryStats,
}
```

### ServiceExport

Service configuration (HTTP endpoint details):

```rust
pub struct ServiceExport {
    pub name: String,              // "openai", "anthropic"
    pub base_url: String,          // "https://api.openai.com"
    pub message_format: MessageFormat,  // OpenAI, Anthropic, Google, Custom
    pub rate_limits: Option<RateLimitsExport>,
    pub model_count: usize,        // Models using this service
}
```

### ModelExport

Model configuration and metadata:

```rust
pub struct ModelExport {
    pub id: String,                // "gpt-4o-mini"
    pub family: String,            // "gpt"
    pub name: String,              // "GPT-4o Mini"
    pub service: String,           // "openai"
    pub version: Option<String>,
    pub variant: Option<String>,   // "mini", "turbo", "haiku"
    pub lab: Option<String>,       // Organization that created it
    pub status: VerificationStatus,
    pub capabilities: Capabilities,
    pub pricing: Pricing,
    pub constraints: Constraints,
    pub use_cases: Vec<String>,
}
```

### RegistryStats

Summary statistics:

```rust
pub struct RegistryStats {
    pub service_count: usize,
    pub family_count: usize,
    pub model_count: usize,
    pub verified_count: usize,
    pub unverified_count: usize,
}
```

## Verification Status

Models have a verification status indicating testing state:

| Status | Description |
|--------|-------------|
| `Verified` | Manually tested and confirmed working |
| `Unverified` | Auto-generated config, not tested (default) |
| `Broken` | Tested but found to have issues |
| `Deprecated` | Model may stop working |
| `Error` | Endpoint returns errors (auth, 500, etc.) |
| `NotFound` | Model not found at provider (404) |

## Type-Safe Configuration Enums

Previously stringly-typed fields are now enums with `Custom(String)` fallback:

### MessageFormat
```rust
pub enum MessageFormat {
    OpenAI,      // OpenAI-compatible (most providers)
    Anthropic,   // Claude message format
    Google,      // Gemini format
    Custom(String),
}
```

### SseParser
```rust
pub enum SseParser {
    OpenAiSse,     // OpenAI SSE format
    AnthropicSse,  // Claude SSE format
    GoogleSse,     // Gemini SSE format
    Custom(String),
}
```

### StreamingFormat
```rust
pub enum StreamingFormat {
    TextEventStream,  // text/event-stream (SSE)
    Ndjson,           // application/x-ndjson
    Custom(String),
}
```

## Usage Examples

### Full Export

```rust
let registry = ModelRegistry::new()?;
let export = registry.export();

println!("Services: {}", export.stats.service_count);
println!("Models: {} ({} verified)",
    export.stats.model_count,
    export.stats.verified_count);
```

### Verified Models Only

```rust
let verified = registry.export_verified();
// Only contains models with status == Verified
```

### Filter by Service

```rust
let anthropic_models = registry.export_by_service("anthropic");
for model in &anthropic_models.models {
    println!("{}: {:?}", model.id, model.status);
}
```

### Filter by Family

```rust
let claude_family = registry.export_by_family("claude");
```

### Direct Methods

```rust
// List only verified model IDs
let verified_ids = registry.list_verified_models();

// Check if specific model is verified
if registry.is_verified("gpt-4o-mini") {
    // Safe to use in production
}

// List by status
let broken = registry.list_models_by_status(VerificationStatus::Broken);
```

## Service Access

Direct service access methods (delegated from ConfigProvider):

```rust
// List all services
let services = registry.list_services(); // ["openai", "anthropic", ...]

// Get service config
let service = registry.get_service("openai")?;
println!("Base URL: {}", service.service.base_url);

// Get model with its service in one call
let (model, service) = registry.get_model_with_service("gpt-4o-mini")?;
```

## Serialization

All export types implement `Serialize` and `Deserialize`, making them suitable for:

- JSON/MessagePack RPC responses
- Caching to disk
- Cross-process communication
- REST API responses

```rust
let export = registry.export();
let json = serde_json::to_string(&export)?;
```

## Performance

The `export()` method iterates through all models and services once, building the complete export structure. For large registries, consider:

1. Using filtered exports (`export_verified()`, `export_by_service()`)
2. Caching the export if the registry doesn't change
3. Using the direct methods (`list_verified_models()`) for simple queries
