# Action Plan: Plugin & Hub Integration

## Overview

Transform cllient so that:
1. `ModelRegistry` can morph into a plugin
2. Any plugin can generate a hub
3. cllient ships a hub binary

---

### 2.2 Create plugin module

**File**: `src/plugin.rs`

```rust
//! Plugin integration for substrate hub
//!
//! Enables mounting ModelRegistry as an Activation plugin.

use crate::{ModelRegistry, ModelConfig, ServiceConfig};
use crate::events::{CompletionEvent, ModelEvent, ServiceEvent, VerifyEvent};
use substrate_core::{
    Activation, PlexusStream, PlexusStreamItem, PlexusError,
    PluginSchema, MethodSchema, wrap_stream,
};
use std::sync::Arc;
use serde::{Deserialize, Serialize};
use serde_json::Value;

/// Activation wrapper for ModelRegistry
pub struct CllientActivation {
    registry: Arc<ModelRegistry>,
}

impl CllientActivation {
    /// Create plugin from registry
    pub fn new(registry: ModelRegistry) -> Self {
        Self { registry: Arc::new(registry) }
    }

    /// Create plugin from shared registry
    pub fn from_shared(registry: Arc<ModelRegistry>) -> Self {
        Self { registry }
    }
}

#[async_trait::async_trait]
impl Activation for CllientActivation {
    fn namespace(&self) -> &str { "cllient" }
    fn version(&self) -> &str { env!("CARGO_PKG_VERSION") }
    fn description(&self) -> &str { "Multi-provider LLM client" }

    fn methods(&self) -> Vec<&str> {
        vec!["complete", "models", "services", "verify", "query"]
    }

    async fn call(&self, method: &str, params: Value) -> Result<PlexusStream, PlexusError> {
        match method {
            "complete" => self.complete(params).await,
            "models" => self.models(params).await,
            "services" => self.services(params).await,
            "verify" => self.verify(params).await,
            "query" => self.query(params).await,
            _ => Err(PlexusError::MethodNotFound {
                method: method.to_string(),
                namespace: self.namespace().to_string(),
            }),
        }
    }

    fn plugin_schema(&self) -> PluginSchema {
        // Generate schema from method signatures
        PluginSchema::leaf(
            self.namespace(),
            self.version(),
            self.description(),
            vec![
                MethodSchema::new("complete", "Execute LLM completion"),
                MethodSchema::new("models", "List available models"),
                MethodSchema::new("services", "List configured services"),
                MethodSchema::new("verify", "Verify model connectivity"),
                MethodSchema::new("query", "Query models with filters"),
            ],
        )
    }
}
```

### 2.4 Add hub convenience methods (feature-gated)

// src/plugin.rs (continued)

#[cfg(feature = "hub")]
impl CllientActivation {
    /// Serve as standalone hub
    pub async fn serve(self, addr: &str) -> anyhow::Result<()> {
        use substrate::Plexus;

        let plexus = Plexus::new().register(self);
        plexus.serve(addr).await
    }

    /// Create Plexus containing this plugin
    pub fn into_plexus(self) -> substrate::Plexus {
        substrate::Plexus::new().register(self)
    }

    /// Mount into existing Plexus
    pub fn mount_into(self, plexus: substrate::Plexus) -> substrate::Plexus {
        plexus.register(self)
    }
}

## Phase 4: Hub Binary

### 4.1 Create cllient-hub binary

**File**: `src/bin/cllient-hub.rs`

```rust
//! Standalone hub server for cllient
//!
//! Exposes ModelRegistry as a substrate Activation over RPC.

use clap::Parser;
use cllient::ModelRegistry;

#[derive(Parser)]
#[command(name = "cllient-hub")]
#[command(about = "Serve cllient as a substrate hub")]
struct Args {
    /// Address to bind to
    #[arg(short, long, default_value = "127.0.0.1:8080")]
    bind: String,

    /// Config directory (optional, uses embedded configs if not specified)
    #[arg(short, long)]
    config: Option<String>,
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    tracing_subscriber::fmt::init();

    let args = Args::parse();

    let registry = match args.config {
        Some(path) => ModelRegistry::from_directory(&path)?,
        None => ModelRegistry::new()?,
    };

    println!("Starting cllient hub on {}", args.bind);
    println!("Models: {}", registry.list_models().len());
    println!("Services: {}", registry.list_services().len());

    registry.serve(&args.bind).await
}
```

## Phase 5: Integration & Testing

### 5.1 Integration test

**File**: `tests/hub_integration.rs`

```rust
#[cfg(feature = "hub")]
mod hub_tests {
    use cllient::ModelRegistry;

    #[tokio::test]
    async fn test_registry_to_plugin() {
        let registry = ModelRegistry::new().unwrap();
        let plugin = registry.into_plugin();

        assert_eq!(plugin.namespace(), "cllient");
        assert!(plugin.methods().contains(&"complete"));
    }

    #[tokio::test]
    async fn test_plugin_schema() {
        let registry = ModelRegistry::new().unwrap();
        let plugin = registry.into_plugin();
        let schema = plugin.plugin_schema();

        assert_eq!(schema.namespace, "cllient");
        assert!(schema.methods.len() >= 5);
    }
}
```

## Parallelization

### Parallel Work Streams

```
Stream A (hypermemetic):          Stream B (cllient):
─────────────────────────         ────────────────────
│                                 │
├─ 1.1 Create substrate-core      ├─ 2.2 Create plugin.rs (stub)
│      (no deps)                  │      (uses substrate-core types)
│                                 │
├─ 1.2 Move types                 ├─ 2.3a complete.rs
│                                 ├─ 2.3b models.rs     } parallel
├─ 1.3 Update substrate           ├─ 2.3c services.rs   } after 2.2
│                                 ├─ 2.3d verify.rs
├─ 1.4 Update hub-macro           │
│                                 ├─ 2.4 Hub methods (after 1.3)
│                                 │
└─ Done                           ├─ 3.1-3.2 Registry methods
                                  │
                                  ├─ 4.1-4.2 Hub binary
                                  │
                                  └─ 5.1-5.2 Tests
```

**Sync points:**
- Stream B waits for substrate-core types (1.1) before plugin.rs (2.2)
- Hub methods (2.4) wait for substrate updates (1.3)
- Everything else is independent

### For 2 Workers

```
Worker A: substrate-core + substrate + hub-macro (hypermemetic)
Worker B: cllient plugin module + methods + binary
```

### For 4 Workers

```
Worker A: substrate-core extraction
Worker B: substrate/hub-macro updates
Worker C: cllient plugin infrastructure (plugin.rs, runtime.rs)
Worker D: cllient activation methods + binary
```

substrate-core creation → plugin.rs types → activation methods → hub binary
        ↓                       ↓                   ↓               ↓
